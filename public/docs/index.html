Philosophy

Margins is for everyone, and our benchmark player is Jack, an early reader. If it works for Jack, it works for everybody. On-screen instructions are one big word at a time, right when it's needed: WALK, JUMP, HURRY, LOOK OUT!, DANGER.

The full philosophy (who it's for, words on screen, look and feel, how levels teach, and what's deliberately saved for later) is the foundation for everything else. Read it before designing anything players will see: docs/PHILOSOPHY.md.

Concept

Everything on the page is drawn in pencil and boils: lines redraw with a small random wobble several times a second, like a flipbook. The light blue ruled lines are platforms, the red margin line on the left is a wall.

The game opens on a comic page: a comic strip drawn in the notebook. Each strip is a row of panels with a title, and each panel is a level. The stick figure walks along the bottom line and jumps up into a panel to play it. The first strip, Getting Started, has one panel: a tutorial where the page draws itself as you walk, the word JUMP is the obstacle, and a sleeping dog waits at the end. The second strip, Launch, is a side-scrolling story level: run through a forest, dodge a UFO, fly a rocket, and dodge a fireball that bursts into fireworks over a city. The third strip, Climb, is a different mode: an endless vertical platformer played in portrait. The comic page is how you pick between them.

Margins is a small proof of concept, built for learning and fun. It uses Phaser 4 (with Arcade physics), Vite, and plain JavaScript. There are no image assets: every line is drawn in code with Phaser.GameObjects.Graphics. It's designed for phone landscape first.

Running it

npm run build    # production build into dist/

On a phone over home Wi-Fi

vite.config.js sets server.host: true, so the dev server listens on the network and prints a Network URL. Open http://<computer-ip>:5173 on the phone and hold it sideways.

WSL2: with WSL's default NAT networking, the phone can't reach the 172.x address Vite prints. Forward the port once from an admin PowerShell, then use the Windows computer's LAN IP from ipconfig (the adapter with a default gateway): 
$wsl = (wsl hostname -I).Trim().Split(" ")[0]
netsh interface portproxy add v4tov4 listenport=5173 listenaddress=0.0.0.0 connectport=5173 connectaddress=$wsl
New-NetFirewallRule -DisplayName "Vite 5173" -Direction Inbound -LocalPort 5173 -Protocol TCP -Action Allow
The WSL address can change after a reboot; rerun the netsh line if the phone stops connecting. The Windows network should be set to Private.

Scenes and the game loop

Each screen is a Phaser scene, listed in main.js; the first one starts the game. Scenes switch with this.scene.start('Key', data).

SceneKeyWhat it does
ComicPageSceneComicPageThe comic page. Jumping into a panel zooms the camera into it and starts that panel's level. Coming back ({ returningFrom: panelId }) zooms out and fades in the panel's finished art.
GettingStartedSceneGettingStartedThe first tutorial panel. Waking the dog marks the panel finished and returns to the comic page.
LaunchSceneLaunchThe Launch level. Reaching the city marks the panel finished and returns to the comic page.
ClimbSceneClimbClimb mode, in portrait. Esc or the ◀ button returns to the comic page.

Phaser calls two methods on the running scene:

  • create(data) runs when the scene starts. It draws the paper, builds platforms and objects, creates the player and its collider, sets up PlayerInput, and calls watchScreen(). Draw order is creation order, so later objects appear on top.
  • update(time, delta) runs every frame: read input with controls.read(), update the player (Arcade physics then moves it and resolves collisions), check the scene's goal, then redraw everything that boils.

The boil

The flipbook look comes from src/pencil.js. Every pencil line is drawn as a handful of short segments, each nudged sideways by a small random amount, in two passes (one darker, one lighter) to look like a real pencil stroke.

The important trick: if the randomness came from Math.random(), every frame would look different and the lines would buzz like TV static. Instead, the random numbers come from a tiny seeded generator (mulberry32), and the seed only changes every BOIL.intervalMs (110 ms, about 9 times a second): 

// Which boil "frame" are we on? Changes every BOIL.intervalMs.
export function boilFrame(timeMs) {
  return Math.floor(timeMs / BOIL.intervalMs);
}

// An rng for one object on the current boil frame. `id` keeps different
// objects from wobbling identically.
export function boilRng(timeMs, id) {
  return makeRng(boilFrame(timeMs) * 7919 + id * 104729);
}

Same seed means the same sequence of random numbers, which means the same wobble. So each object can safely redraw every frame (the stick figure has to, because it moves), and its lines hold perfectly still until the next boil tick, when they all jump to a new shape at once.

The helpers you can call:

FunctionWhat it does
boilRng(time, id)Returns a random-number function for this object on the current boil frame.
pencilLine(g, rng, x1, y1, x2, y2, opts)Wobbly line. Options: color, width, alpha, wobble (px), passes.
pencilCircle(g, rng, cx, cy, r, opts)Wobbly closed loop. Same options plus points.

The paper itself doesn't boil: real notebook paper is printed, not hand-drawn. Platforms are traced over their blue ruled line in boiling pencil, with small end ticks so you can tell which line segments are solid.

Physics, platforms & the wall

Margins uses Phaser's Arcade physics: simple axis-aligned boxes with gravity (1400 px/s²). Nothing physical has a sprite. Each body is attached to a Zone, an invisible rectangle, and the visuals are drawn separately in pencil.

  • Platforms are zones in a static group: bodies that never move. Each one's top edge sits exactly on a ruled line and is 10 px thick below it.
  • One-way platforms: every platform except the floor turns off collision on its bottom and sides (body.checkCollision.down = false, and the same for left and right), so you can jump up through it from below and land on top.
  • The floor is solid, runs from the margin to the far edge of the page, and sits on ruled line 12 (y = 504).
  • The wall is a tall static zone just left of the red margin line, so the figure stops right at the line.
  • World bounds keep the player on screen. They're updated whenever the screen size changes.

The stick figure

StickFigure owns a 20 × 60 px physics box and a Graphics object it clears and redraws every frame. The figure is described in figure space: u to the right, v up from the feet. A toScreen(u, v) helper turns that into screen coordinates, mirroring u for the facing direction and applying squash and stretch.

Walk cycle

While moving on the ground, walkPhase advances (dt × 14). Each leg's angle is a sine wave of the phase (plus a small base spread so the legs don't overlap when standing), and the arms swing opposite to the legs. When the figure stops, the phase resets to standing.

Jump feel

Three standard platformer tricks make jumping forgiving (players press a hair too early or too late all the time, especially young ones) and expressive. All three live in StickFigure.update() and work the same on keyboard and touch. The design notes are in docs/superpowers/specs/2026-11-02-jump-feel-design.md.

  • Coyote time (coyoteTimeMs, 100 ms): after walking off the edge of a line, you can still jump for a moment, like a cartoon coyote running off a cliff. coyoteTimer stays full while on the floor and drains once you leave it.
  • Jump buffering (jumpBufferMs, 120 ms): a jump pressed just before landing is remembered in jumpBufferTimer and fires on the landing frame.
  • Variable jump height (jumpCutMultiplier, 0.5): letting go of jump while still rising multiplies the upward speed by 0.5, so a tap is a small hop and holding is the full jump.
  • A jump uses up both timers, so mashing jump can't double jump. Timers are checked before they drain each frame, so each window lasts its full configured length.

Jumping, squash and stretch

  • Take-off: velocity is set to −620 px/s, and the figure stretches to 0.8 × 1.25 (thin and tall).
  • In the air: a fixed pose with legs apart and arms up, slightly different rising and falling.
  • Landing (on the ground now, not last frame): squash to 1.3 × 0.7 (wide and short).
  • Both scales ease back to 1 using 1 − e−12·dt, which behaves the same at any frame rate.

The head uses the average of the two scales so it stays round instead of turning into an egg.

Fitting any screen

Each scene starts by choosing its layout with useLayout(this, LANDSCAPE) or useLayout(this, PORTRAIT) (screen.js). The story scenes are designed in 960 × 540; Climb is designed in 540 × 960. useLayout() changes the design size in the game config and refreshes the scale manager, so EXPAND rescales the whole game. It also sets <body data-orientation>, which index.html uses to show a wordless "turn your phone" drawing when a phone is held the wrong way for the current scene.

For the landscape scenes:

The level is laid out in a 960 × 540 area (16:9) that is always fully visible. The game uses Phaser.Scale.EXPAND: it scales that area to the screen, then grows the game in whichever direction has room left over, so there are never black bars.

  • Wider screens (most phones are about 19.5:9): the page simply continues to the right. The paper and floor are drawn PAGE_MAX_WIDTH (2400 px) wide to cover any screen.
  • Taller screens (tablets): fitToScreen() in screen.js scrolls the camera up so the floor stays at the bottom, and the extra paper appears above the top ruled line as a blank header.
  • fitToScreen() also resets the physics world bounds. It runs at start and on every Phaser resize event (rotation, the mobile address bar hiding, a resized window). The listener is removed on scene shutdown so restarts don't stack up duplicates.
  • Climb handles its own camera (it scrolls up forever) and centers its 540-wide page on wider screens, with the desk showing on either side. It passes its own fit function: watchScreen(this, fit).
  • Anything pinned to the screen rather than the page (like the touch buttons) uses this.scale.width/height and setScrollFactor(0).

Touch controls

TouchControls only appears on touch devices (game.device.input.touch). Instead of listening for button press and release events, every frame it loops over all of Phaser's pointers and checks which buttons a finger is currently over (with a hit area 1.25× the drawn circle). That handles multi-touch and sliding a thumb between buttons with no extra bookkeeping. main.js sets input.activePointers: 3 so several fingers are tracked at once.

The buttons are placed from the screen's corners. In landscape the arrows start just right of the margin; in portrait (Climb), where the screen is narrow, they start near the left edge.

The jump button is converted into a single-frame press in PlayerInput.read() (input.js) (down now, not down last frame), so holding it doesn't bunny-hop. Its held state is passed along as jumpHeld, so holding ▲ jumps higher, just like holding the key.

The comic page and levels

Getting Started (the first panel)

  1. The page draws itself. The floor's pencil trace has a drawnTo x position. A DrawingPencil pushes it forward at 520 px/s, staying 170 px ahead of the figure (faster than he walks, so he never catches it). WALK is written at the start and fades once he walks.
  2. The word is the obstacle. JUMP is a PencilWord 46 px tall standing on the line. Each letter's box is added with platforms.addSolid(), so walking into the J stops you, and the gaps between letters are narrower than the figure, so he walks across the tops. The letters are written on when the pencil reaches them.
  3. A friend at the end. A sleeping Dog in a coffee ring, revealed when the pencil gets there. Touching him wakes him (hop, wag, heart), marks the panel finished with markComplete(), and fades back to the comic page.

There's no way to fail: the floor is solid all the way across.

Words on screen: PencilWord

new PencilWord(scene, 'JUMP', x, y, size, opts) writes a word in boiling pencil using a tiny stroke font in PencilWord.js (A–Z, 0–9, and !). { written: false } starts it blank and write(ms) writes it on stroke by stroke; fadeOut(ms) erases it (one word at a time); letterBoxes() gives each letter's box. Only the letters used so far exist; add a letter by sketching its strokes in a 1-unit-tall box. Words must follow the philosophy: one big early-reader word, right when it's needed.

Adding a panel

  1. Write a scene for the level (copy GettingStartedScene for the basics) and add it to the list in main.js.
  2. When the level is finished, call markComplete(panelId) and this.scene.start('ComicPage', { returningFrom: panelId }).
  3. Add the panel to ComicPageScene and give ComicPanel its art.

Platforms are described by ruled line, not pixels: { line: 9, from: 190, to: 360, oneWay: true }. Line 0 is the top ruled line (y = 72, see lineY()), lines are 36 px apart, and the floor is line 12.

Climbing 3 lines uses almost the whole jump and needs jump held, so keep horizontal gaps small (40 px or less) for those. A tap reliably clears one ruled line. Keep everything a level needs inside the 960 × 540 area, since on a 16:9 screen nothing outside it is visible.

Launch

A long, side-scrolling level on one long sheet of paper. The camera follows the figure to the right and stops at the city. Phases (in LaunchScene): run → launching → flying → landing → done.

BeatWorld xWhat happens
Forest0 – 2600Run, jump logs, collect stars. Parallax pencil trees. WALK.
UFO chase1300 – 3300HURRY! A saucer with an alien drops glowing goo after a warning (rays under it).

Fireballfrom 5200LOOK OUT! It follows your height, shows a dashed line, then lunges along it. Three times.

Getting hit (goo or fireball) is gentle: a one-second stun and a knock back, never a game over. Fire gets a warm fill (COLORS.fire), the only color in this level.

Sound lives in src/audio.js and is made in code with the Web Audio API (no audio files): a short music loop that gets busier in the chase and faster in the finale, a fanfare, and sound effects. There is one AudioContext, created on the first tap or keypress (phones require it); Phaser's own audio is turned off. The mute setting is saved in localStorage. Only Launch plays sound for now. During flight, TouchControls.setLayout('flight') swaps in ▲ ▼ buttons and PlayerInput reports up and down.

Climb mode

An endless vertical platformer in portrait. The figure walks and jumps exactly like in the story levels (same jump, jump feel, and controls). The camera follows upward and never scrolls back down, so falling off the bottom of the screen ends the run, and so does touching an ink blot. Design notes: docs/superpowers/specs/2026-11-02-climb-mode-design.md and 2026-11-02-climb-extensions-design.md.

Initials, start screen, and high scores

  • First time: an initials card. Three letter slots, each with ▲ ▼ buttons, and ✓ to finish. Keyboard: Up/Down change the letter, Left/Right move between slots, typing a letter fills the slot, Enter finishes. No typing needed, so kids can do it.
  • Start card (every time Climb opens from the comic page): your initials, a pencil button to change them, and a big ▶. Keyboard: Left/Right choose a button, Enter/Space press it.
  • Score card after a run: the total, ↑ lines and ★ stars, and the top five with initials. A new high score is boxed in pencil with a star beside it. ↻ starts again right away (skipping the start card), ◀ goes back to the comic page.
  • Initials and the top five live in localStorage (progress.js: getInitials, setInitials, highScores, addHighScore), best effort. The Climb panel on the comic page shows the top score.
  • The cards are in objects/ClimbCards.js (InitialsCard, StartCard, ScoreCard), sharing a Card base with pencil buttons and icons.

Milestones and difficulty

Height is counted in ruled lines climbed (1 point each). Crossing a milestone writes its number and one word near the top of the screen. The whole table is CLIMB.milestones in config.js: each entry lists only what changes at that height, and everything else carries forward. milestones.js turns it into settings with difficultyAt(lines) and finds what to announce with milestoneAt(lines).

LinesWordWhat changes
0—Wide platforms, gaps of 1–2 lines, lots of stars
100GO!More stars, coil springs, gaps up to 3 lines
200LOOK OUT!Ink blots (slow), paperclips
500UP!Paper airplanes, more and faster blots, stars and blots worth more, smaller platforms
1000DANGERBlots chase you along their line; faster; smaller platforms; bigger rewards
every 500 afterHURRY!CLIMB.beyond.step: more and faster blots, narrower platforms, bigger rewards, within CLIMB.beyond.limits

Reachability is a hard limit, separate from the table: CLIMB.reach caps gaps at 3 ruled lines and sideways steps at 170 px (what a held jump can do), so rebalancing can't create an impossible climb.

Debugging

  • Set debug: true under physics.arcade in src/main.js to see the physics boxes.
  • In dev mode the game is exposed as window.game. Try game.scene.getScene('GettingStarted').player in the browser console, or jump straight to a mode with game.scene.getScene('ComicPage').scene.start('Climb').

Deployment

Every push to main runs .github/workflows/deploy.yml: npm ci, npm run build, then publishes dist/ to GitHub Pages. It can also be run by hand from the repository's Actions tab.

Working on Margins

  • Read docs/PHILOSOPHY.md first, and run the "Jack test" on anything players will see.
  • Build only what's been agreed. "Someday" ideas go in the philosophy's "Not yet" list instead of into code.
  • Keep magic numbers in config.js, and keep each file about one thing.
  • The code is meant to be read by someone learning: short functions, clear names, and comments that explain why.
  • Test on a phone in landscape. That's the main target.
  • When behavior, controls, structure, or tuning defaults change, update this page (public/docs/index.html) and CLAUDE.md in the same commit.
